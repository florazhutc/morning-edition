Source: original article

'Unprecedented' Cyberattack cripples supermarket fridges across Europe as hackers activate automatic defrosting  — delivery and store prices also impacted by incident | Tom's Hardware

Actionable Insight

A cyberattack has reportedly caused widespread disruption by activating automatic defrosting in supermarket refrigeration systems across Europe, impacting food supply and prices. Initial analysis suggests the incident may stem from gross negligence, possibly involving easily guessable default passwords or unpatched vulnerabilities. This highlights critical security gaps in connected infrastructure and the potential for significant real-world consequences from such breaches.

Community Voice

The community largely debates whether this was a sophisticated hack or a result of gross negligence, with one comment pointing to a default 'admin' username and a password reset daily to the current date. There's speculation linking the incident to a recently disclosed Danfoss or Claroty vulnerability, and some suggest a similar attack occurred on US military bases. Concerns are raised about the necessity of internet connectivity for such systems and the lack of physical bypasses for manual control. One comment clarifies the scope, mentioning three French supermarket chains and a separate cybersecurity incident affecting a chain in Belgium and the Netherlands.

Actionable Insight

This project statically recompiles PlayStation 2 games' native code into C++ and then WebAssembly, enabling them to run directly in a web browser. It bypasses traditional emulation by translating the Emotion Engine machine code ahead of time and linking it with a WebGPU-powered reimplementation of the PS2's operating system and hardware. This method offers a novel approach to preserving and playing classic console games on modern web platforms.

Developer Tools 🛠️

Codex CLI Defaults to Persistent, Self-Updating Background Daemon

Source: original article

CLI: make `daemon_auto_start` opt-in — a persistent, self-updating background daemon shouldn't be the default · Issue #48195 · openai/codex · GitHub You signed in with another tab or window. Reload to refresh your session. You signed out in another tab or window. Reload to refresh your session.

Actionable Insight

The Codex CLI installs a persistent, self-updating background daemon by default, a design choice users argue should be opt-in. This approach leads to significant issues, including excessive disk usage from storing old versions and numerous bugs during auto-updates, such as file permission corruption. The lack of transparent control and stability concerns highlight a tension between rapid development and user control in developer tools.

Community Voice

Users report the daemon consumes substantial disk space, with one user noting 12GB from old versions, and is prone to bugs, including auto-update failures that corrupt file permissions. Many find Codex's structure problematic, mixing state and configuration, which complicates declarative management and leads some to abandon the tool. While some argue auto-updates are standard for fast-moving software, others prefer minimal harnesses for greater control and reliability, noting similar over-engineering in tools like Claude Code. A hidden feature flag `daemon_auto_start = false` exists in `~/.codex/config.toml` to disable the auto-start, but it is not officially documented.

Actionable Insight

Browser fingerprinting allows websites to uniquely identify users across different devices and sessions, creating persistent profiles. This technique, often employed for targeted advertising, can gather extensive personal data, potentially exceeding what users or their acquaintances know. It highlights a shift from traditional cookie-based tracking to more sophisticated, script-driven methods for user profiling.

Community Voice

Commenters debate the role of JavaScript in enabling extensive fingerprinting, questioning why high-entropy browser APIs aren't consent-gated. Atticus: macOS Hold-to-Talk Voice Assistant Blends Local Processing with Claude AI for Speed

Source: Hacker News post

Hi HN! I'm Saarth. I'm in 9th grade, and I built Atticus. Atticus is a fast and cheap Mac assistant that can do tasks for you. You hold down Control-Option-Space, speak or type your task, be it complex or a simple browser search, and Atticus will get on it. The interesting part is that simple tasks, like opening apps, playing a Spotify playlist, or web queries, don't touch AI, and instead are processed locally and typically finish in under a second. For example, prompting Atticus to open apps takes around 0.08 seconds, sometimes even finishing before you finish your sentence, sort of like Jev.

Actionable Insight

Atticus distinguishes itself as a macOS voice assistant by employing a hybrid processing model, handling simple tasks locally for near-instant execution and offloading complex queries to Claude AI. This architecture aims to deliver both speed and versatility, addressing the common challenge of latency in AI-powered assistants. Its ability to perform basic actions like opening apps in milliseconds highlights a focus on user experience.

Community Voice

The community largely praised Atticus, noting its impressive functionality and suggesting it represents what Apple's own AI should be. Primary concerns revolved around data privacy when sending information to Anthropic and a strong desire for local AI processing options, ideally supporting the OpenAI API standard. Other discussions included potential voice transcription inaccuracies, interest in Windows and Linux versions, and suggestions for integrating cheaper cloud LLMs.
