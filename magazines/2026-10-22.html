eMudhra Certificate Authority Keys Found to Be Extremely Weak and Easily Cracked

Source: original article

Eight Bits of Trust; eMudhra's CA keys cracked in milliseconds One of eMudhra's certificate authority private keys is the number 4. Not a number that starts with 4, or the number 4 followed by a few hundred random digits, just, 4... Another one is 56, and another is 115. I know, because I recovered all of them from their public certificates on my laptop just now, and it took less than a second.

Actionable Insight

eMudhra, a Certificate Authority, was found to have used extremely weak private keys, some as simple as single-digit numbers, which were easily recovered in milliseconds. This critical failure in cryptographic practice severely compromises the integrity of digital certificates issued by eMudhra. The incident highlights significant vulnerabilities in the trust chain, particularly for unpatchable devices that rely on these compromised certificates.

Community Voice

The community noted the ease of discovery using Google's `paranoid_crypto` tool and expressed significant concern over the implications for unpatchable IoT devices, with some suggesting the compromised keys could be used for jailbreaking. While eMudhra claimed most affected keys were not in production and none issued end-entity certificates, the incident reignited discussions on the excessive number of trusted CAs and the need for stronger security measures like DANE or Certificate Transparency logs. The sheer simplicity of the compromised keys was also highlighted as a surprisingly 'silly' cause for such a severe security failure.

Use flat file layout for rust_library sources [chrome] Name source files and leaf modules after the primary user-defined item A use statement should import items from one module Qualify calls to top-level functions with a module name Type names should be imported and used unqualified

Actionable Insight

Google's Rust Style Guide outlines conventions for project structure, including a flat file layout for library sources and specific naming for modules and files. It also details practices for `use` statements, requiring single-module imports, and dictates that type names should be imported and used unqualified. This guide aims to standardize Rust development within large projects like Chromium.
